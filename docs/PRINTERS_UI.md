# Printers UI

The Printers workspace reads the authenticated `GET /api/v1/printers` fleet-health endpoint every five seconds. It presents the printers registered at API startup, their connection state, queued tickets, successful prints, failures, and measured busy-time utilization since the current API process started. Each health record includes `busy_ms`, `utilization`, and `utilization_available`; utilization is the percentage of manager uptime spent processing jobs for that printer, including retries.

Network addresses, printer-driver configuration, and routing remain server-side configuration. They are deliberately not returned by the API or exposed in the browser. The API registers separate `kitchen` and `cashier` destinations at startup; configure `PRINTER_KITCHEN_ADDRESS` and `PRINTER_CASHIER_ADDRESS` for raw-TCP ESC/POS hardware, or leave either empty for its local mock driver. `PRINTER_RECONNECT_INTERVAL` controls the background health loop and defaults to five seconds. A failed initial connection does not prevent the printer manager from starting, and offline drivers are retried even when no ticket is waiting. Ticket submission and reprinting continue through the existing authenticated printer endpoints.
