# Print Queue UI

The Print Queue workspace refreshes durable jobs every two seconds. It shows queue state, ticket detail, attempt count, errors, requeue actions, retry actions, and reprint actions. Requeue is shown only for jobs still marked `printing` after operator review. A successful requeue changes the source job to `reviewed` and creates a queued replacement, preserving a clear audit trail without leaving the source looking active. Retry is shown only for failed jobs and creates a new durable ticket from that exact failed job. Reprints create a new durable job from the latest stored ticket for the order, so the workflow does not depend on the printer manager's in-memory history. On API startup, jobs left in `queued` state are claimed before dispatch so concurrent API instances do not replay the same ticket. Jobs already in `printing` stay available for operator review to avoid duplicate physical tickets and also appear as printer-anomaly insights.
